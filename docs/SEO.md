# Search Engine Optimization (SEO) & Indexing Guide

This document describes how search engines discover, crawl, and index `gurmesa.tech` across Google, Bing, and Edge, along with step-by-step instructions for site ownership verification and sitemap submission.

---

## 1. Architecture & Crawling Overview

### Base URL Resolution
The canonical production origin is configured via `NEXT_PUBLIC_SITE_URL` or `SITE_URL` (defaults to `https://gurmesa.tech` when `APP_ENV=production`). All sitemap entries and metadata canonicals resolve to this origin without trailing slashes.

### Sitemap (`/sitemap.xml`)
Next.js dynamically serves the sitemap from `app/sitemap.ts` (`MetadataRoute.Sitemap`).
- **URL**: `https://gurmesa.tech/sitemap.xml`
- **Revalidation**: `export const revalidate = 3600` (1 hour ISR cache). Also purged on content updates via `revalidatePublicContent()` in `lib/revalidate.ts`.
- **Locale Routing**:
  - English (default / root): `/`, `/about`, `/services`, `/work`, `/blog`, `/contact`, `/privacy`, `/terms`, `/testimonials`
  - Amharic: `/am`, `/am/about`, `/am/services`, ...
  - Afaan Oromo: `/om`, `/om/about`, `/om/services`, ...
- **Hreflang Alternates**: Every `<url>` element in `sitemap.xml` includes `xhtml:link` tags for `en`, `am`, `om`, and `x-default` (pointing to the English URL).
- **Dynamic Content**:
  - **Services**: All active services across all 3 locales (`/services/[slug]`).
  - **Projects / Case Studies**: Only `status = 'PUBLISHED'` and confidentiality is `PUBLIC` or `ANONYMIZED`. **NEVER** includes `PRIVATE` projects or draft case studies.
  - **Blog Posts**: Only published blog posts (`status = 'PUBLISHED'`).
- **Sorting**: Sitemaps are sorted deterministically (static routes first, then sorted by path ascending) to ensure stable crawl fingerprints.
- **Resilience**: Dynamic database fetches use `Promise.allSettled`. If a database error occurs, the sitemap falls back gracefully to static pages instead of returning an HTTP 500.

### Robots Configuration (`/robots.txt`)
Dynamically generated by `app/robots.ts`:
- **Production (`APP_ENV=production`)**:
  - `User-agent: *`
  - `Allow: /`
  - `Disallow: /admin`
  - `Disallow: /api/`
  - `Disallow: /mock-storage/`
  - `Sitemap: https://gurmesa.tech/sitemap.xml`
- **Non-Production (`APP_ENV !== 'production'`)**:
  - `Disallow: /` (protects staging, preview, and test environments from indexation).

### In-Page Metadata & Alternates
Every public page exports `generateMetadata`:
- **Canonical**: Self-referencing URL for current locale (`canonical: 'https://gurmesa.tech/...'`).
- **Alternates**: Hreflang links for `en`, `am`, `om`, and `x-default`.
- **Admin Isolation**: `app/(admin)/layout.tsx` enforces `robots: { index: false, follow: false }`.

## 2. Owner Submission Steps for Google Search Console (GSC)

### Step 2.1: Add Property in Google Search Console
1. Visit [Google Search Console](https://search.google.com/search-console).
2. Click **Add Property**.
3. Choose **Domain Property** for `gurmesa.tech` (recommended) or **URL prefix** (`https://gurmesa.tech`).
4. **Verification**:
   - **Method A (Recommended - Domain Property)**: Add the `TXT` record provided by Google to your DNS provider (Cloudflare, Namecheap, Route 53, etc.).
   - **Method B (HTML Tag - URL Prefix)**: Copy the verification code from `<meta name="google-site-verification" content="TOKEN" />`, add it to your hosting environment variables as `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION=TOKEN`, and trigger a redeploy.

### Step 2.2: Submit Sitemap
1. In Google Search Console, navigate to the **Sitemaps** section in the left sidebar.
2. Under "Add a new sitemap", enter:
   ```text
   sitemap.xml
   ```
3. Click **Submit**.
4. Confirm status shows "Success" with the discovered page count.

### Step 2.3: Request Home Page Indexing
1. Use the **URL Inspection** search bar at the top of GSC.
2. Enter `https://gurmesa.tech/`.
3. Once the live inspection completes, click **Request Indexing**.
4. (Optional) Repeat for key pillar pages: `https://gurmesa.tech/services` and `https://gurmesa.tech/work`.

## 3. Owner Submission Steps for Bing Webmaster Tools & Edge

Edge uses the Bing search index. Submitting to Bing Webmaster Tools covers Edge and Copilot search.

### Step 3.1: Sign In & Import from GSC
1. Visit [Bing Webmaster Tools](https://www.bing.com/webmasters).
2. Sign in with your Google Account or Microsoft Account.
3. Click **Import from Google Search Console**.
   - This automatically copies your verified domain, DNS verification, and submitted sitemaps with zero manual configuration.
4. *Alternatively*, add `https://gurmesa.tech` manually and set `NEXT_PUBLIC_BING_SITE_VERIFICATION=TOKEN` in your environment variables.

### Step 3.2: Verify Sitemap in Bing
1. Go to **Sitemaps** in the Bing Webmaster Tools sidebar.
2. If not imported automatically, submit `https://gurmesa.tech/sitemap.xml`.
3. Ensure status displays "Success".

## 4. Verification & Health Check

### Local / CLI Verification Script
A health-check script is provided at `scripts/check-sitemap.mjs`:
```bash
node scripts/check-sitemap.mjs https://gurmesa.tech
```
This script:
1. Fetches `/robots.txt` and verifies allow/disallow directives and sitemap linkage.
2. Fetches `/sitemap.xml` and parses all `<loc>` entries.
3. Sequentially requests each page (`redirect: 'manual'`) with rate pacing.
4. Checks that each URL returns HTTP 200, matches the origin, contains no `X-Robots-Tag: noindex`, and does not have `<meta name="robots" content="noindex">`.
5. Outputs a summary table of inspected URLs.

### Search Engine Index Verification
Within 24–72 hours of submission:
- Query Google: `site:gurmesa.tech`
- Query Bing: `site:gurmesa.tech`
Verify that `gurmesa.tech`, `/am`, and `/om` appear in search results with appropriate page titles and descriptions.
